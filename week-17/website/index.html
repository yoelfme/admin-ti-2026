Infrastructure as Code

Define, version, and automate cloud resources the same way you manage application source code.

What is IaC?

Infrastructure as Code (IaC) means describing servers, networks, storage, and other cloud resources in machine-readable files instead of clicking through a portal or running ad-hoc scripts.

You write a desired state—for example, “one resource group and one storage account”—and a tool compares that declaration to what already exists in the cloud, then creates, updates, or removes resources to match.

Why use it?

  • Repeatable Spin up identical dev, staging, and production environments from the same definitions.
  • Version controlled Track every infrastructure change in Git with reviews, diffs, and rollback.
  • Documented by default The code is the specification—no separate runbooks that drift out of date.
  • Automated Run preview and up (or equivalent) in CI/CD instead of manual console work.

Core concepts

  • Declarative You describe what you want, not the step-by-step shell commands to get there.
  • State & plan Tools compute a plan (diff) before applying changes so you can review impact first.
  • Idempotency Running the same deployment twice should converge to the same end state without duplicates.
  • Providers Plugins talk to Azure, AWS, GCP, Kubernetes, and hundreds of other APIs from one workflow.

Typical workflow

Write code → Preview plan → Review diff → Apply → Export outputs

Popular tools include Terraform, Pulumi, AWS CloudFormation, and Azure Bicep. This project uses Pulumi with Python to provision Azure resources. 

# Example: declare a storage account in code
account = storage.StorageAccount(
    "sa",
    resource_group_name=resource_group.name,
    sku={"name": storage.SkuName.STANDARD_LRS},
    kind=storage.Kind.STORAGE_V2,
)

Good practices

  • Small, focused stacks Split large environments into manageable projects with clear ownership.
  • Secrets outside code Use vaults, environment variables, or Pulumi config encryption—never commit keys.
  • Preview in CI Run plans on every pull request so reviewers see infrastructure changes early.
